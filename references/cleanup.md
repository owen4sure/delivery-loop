# 清理標準

目的：測試站、暫存資料、臨時服務用完就收掉，電腦空間和記憶體才不會越堆越滿；同時保證不會刪到還要用的東西。使用者不必自己動手，也不必擔心刪錯。

## 建立時就記下來

每建立一樣東西，當下就寫進 `.done-done/CREATED.md`：

```markdown
## C1 預約功能測試站
- 種類: 測試站
- 位置: booking-test.localhost（從 2026-10-25 的主站備份還原）
- 工作單: T05, T06
- 狀態: 使用中
- 清理方式: 刪除這個站與它的資料庫；主站備份保留
```

狀態只用四種：使用中、隔離中、已清理、保留（要寫理由）。

## 可以自己清的條件（全部符合才可以）

1. 記在 CREATED.md，是這個專案自己建的。
2. 相關工作單都已 done 或 dropped，或所屬里程碑已 released。
3. 沒有在用：沒有程序開著它，沒有設定檔（網頁伺服器、容器設定、站台設定、排程）指到它，最近 24 小時沒有被寫入。
4. 不是唯一一份：裡面的東西能重建，或已有其他備份。要留的證據（截圖、紀錄）先搬到專案的證據資料夾。
5. 不屬於絕對不刪的東西（見下方）。

檢查程式會提醒「相關工作單都完成了，但還標使用中」的項目。

## 怎麼清

1. 記下位置和大小。
2. **先隔離**：改名、移到封存區、停用服務。資料庫先確認有備份，或它本來就是從備份還原的副本。
3. 觀察至少 24 小時，或到下一個里程碑，確認沒有東西壞掉。狀態改成「隔離中」。
4. 再真的刪除，在 LOG.md 記一行：刪了什麼、多大、要怎麼還原（如果可以）。
5. 把 CREATED.md 的狀態改成「已清理」。

## 絕對不刪

- 使用者的資料、主站、正式站、GOAL.md 列的受保護資源。
- 最近一份確認還原得回來的備份，以及部署回復要用的備份。
- Git 歷史、沒提交的修改、別人的分支或工作目錄。
- 不屬於這個專案的服務、容器、檔案。
- 任何還在用、或被設定檔指到的東西。

## 不是自己建的東西

舊的測試站或暫存檔，如果沒記在 CREATED.md：

- 同時能證明下面三件事，才可以照上面的流程清：
  1. 是 agent 建的：從命名、建立紀錄、對話紀錄看得出來。
  2. 沒有在用：照「可以自己清的條件」第 3 點檢查。
  3. 有備份或能重建。
- 證明不了，就列進問題文件的「需要你回答」，寫清楚位置、大小、為什麼覺得可以刪、刪了會怎樣，讓使用者一次決定。

## 什麼時候不清

- 截止時間前 6 小時內。
- 發布或部署進行中。
- 有 doing 的工作單正在用它。

## 空間或記憶體吃緊時

先清自己建的、已確定不用的東西；還不夠，再把候選列進問題文件問使用者。不能因為吃緊，就停掉不屬於這個專案的服務。
